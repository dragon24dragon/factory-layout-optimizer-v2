# 設計｜工場レイアウト設計最適化ツール PoC（v2）

要件は [要件定義.md](要件定義.md)。この文書は**作りの中身**を書く。

---

## 1. 全体の流れ

```
data/sample_factory.json（工場・設備・搬送回数・安全基準・固定物）
        ↓ app.py が読み込む
Factory / Area（models.py のデータの形）
        ↓
generate_ranked_layouts（generator.py）
   ├─ expand_areas            台数ぶんに展開（例：マシニングセンタ4台 → 4つ）
   ├─ generate_candidate_layouts
   │     └─ generate_grid_layout   左下から順に詰めて1案を作る（並び順をずらして複数案）
   └─ rank_candidate_layouts（scoring.py）
         └─ total_weighted_flow_distance   距離 × 1日の搬送回数 の合計
        ↓
スコアの小さい順に並んだ候補
        ↓ app.py
ランキング表 ＋ 上位3案の配置図（matplotlib）
```

---

## 2. ファイルの役割

**計算（`layout_optimizer/`）と画面（`app.py`）を分けている。画面を開かずにテストできる。**

| ファイル | 役割 | やらないこと |
|---|---|---|
| `models.py` | **データの形**（`Factory`／`Area`／`PlacedArea`） | 計算 |
| `constraints.py` | **条件の判定**（はみ出し・重なり・距離・壁・柱・非常口・溶接） | 配置を決めること |
| `scoring.py` | **評価**（中心間の距離 × 搬送回数の合計、順位づけ） | 配置を作ること |
| `generator.py` | **候補を作る**（台数展開・グリッド配置・並べ替え・順位づけの呼び出し） | 描画 |
| `validation.py` | **入力値の検査**（工場サイズ・設備の値） | 配置の判定 |
| `app.py` | **画面**（入力の表示・条件の指定・実行・図の描画） | 計算 |

**依存の向き**

```
models.py → constraints.py / scoring.py / validation.py → generator.py → app.py
```

`layout_optimizer/` は画面を知らない。`app.py` は計算をしない。

## 3. データの形（`models.py`）

| クラス | 持つもの |
|---|---|
| `Factory` | `width_m`／`height_m` |
| `Area` | `id`／`name`／`count`／`width_m`／`height_m` |
| `PlacedArea` | `area`（上の `Area`）／`x_m`／`y_m`（**左下の座標**） |

**長方形は「左下の座標＋幅＋奥行き」で表す。** 回転は扱わない。

---

## 4. 判定のルール（`constraints.py`）

**あいまいさが残らないよう、言葉ではなく式で決めている。**

| 判定 | ルール |
|---|---|
| **はみ出さない** | `0 ≤ 左` かつ `右 ≤ 工場幅`（縦も同じ） |
| **重ならない** | 片方が完全に左右どちらか、または上下どちらかにある＝重ならない。**辺が接するのはOK** |
| **面と面の距離** | 横の隙間と縦の隙間を出し、`hypot(横, 縦)`。**重なっていれば0** |
| **最小距離** | 面と面の距離 ≥ 指定値 |
| **壁からの離隔** | 左・下・右・上の余白がすべて指定値以上 |
| **柱からの離隔** | 設備と柱の面間距離 ≥ 指定値 |
| **非常口前** | 非常口前の確保エリアと**重ならない** |
| **溶接の離隔** | 溶接エリアと相手の面間距離 ≥ 5.0m（既定値） |

## 5. 候補の作り方（`generator.py`）

### `expand_areas`
台数ぶんに展開する。**2台以上のときだけ名前と ID に連番を付ける**
（例：`cutting_machine` → `cutting_machine_1`・`cutting_machine_2`、名前は「切断機1」「切断機2」）。
1台のものは元の ID のまま。**搬送回数の区間指定（`daily_flows`）が ID で引けるようにするため。**

### `generate_grid_layout`
左下から右へ順に置き、**右端（工場幅 − 壁からの距離）を超えたら次の段へ改行**する。
段の高さは、その段で最も高い設備に合わせる。設備の間隔は `gap_m`（既定2.0m）。
**上端を超えて置けないときは、日本語のエラーを出す**
（`〇〇を配置できません。工場内のスペースが不足しています。`）。

### `generate_candidate_layouts`
**設備の並び順を1つずつずらして**（回転シフト）、候補を作る。
候補数は「指定数」と「設備の総数」の小さいほう。**同じ並びの重複は作らない。**

---

## 6. 評価のしかた（`scoring.py`）

```
スコア ＝ Σ（区間の中心間距離 × その区間の1日あたり搬送回数）
```

- 距離は**中心と中心の直線距離**（`math.hypot`）
- `daily_flows` の `from`／`to` が**その案に無ければ、その区間は飛ばす**
  （例：`machining_center_or_lathe` のような、実在しない ID の区間）
- スコアは**小さいほど良い**。小さい順に並べて順位をつける

## 7. 画面（`app.py`）

| 部分 | 中身 |
|---|---|
| 入力データ | 工場の幅・奥行き・設備の種類数。設備一覧は折りたたみ |
| 探索条件 | **生成する候補数**（1〜20・既定5）／**外壁からの距離**（既定1.0m）／**設備間の基本間隔**（既定2.0m） |
| 実行 | ボタンを押すと生成 → ランキング表 → **上位3案の配置図** |
| 図 | matplotlib。グリッド表示、設備は枠線のみ、中央に名称 |
| エラー | 置けないときは `st.error` で日本語表示し、そこで止める |

**日本語の文字化け対策**：`Yu Gothic` → `Meiryo` → `MS Gothic` の順に、入っているフォントを探して使う。

**文字が枠からはみ出す問題への対応（10/1 修正）**：
設備の幅だけでなく**名前の長さも見て**文字サイズを決める。長い名前のときだけ小さくなり、
大きくなることはない（最小3.5pt）。`clip_on=True` で枠外にはみ出さない。

## 9. 今の設計の弱いところ

| 弱点 | 中身 |
|---|---|
| **条件判定が配置に効いていない** | `constraints.py` の関数を `generator.py` が呼んでいない。**条件を満たさない案も候補に残る** |
| **固定物を避けていない** | 柱・電気室・非常口前が「置けない場所」として扱われていない |
| 候補の作り方が単純 | 並び順をずらすだけ。**似た案が並びやすい** |
| 通路の概念がない | 設備間は一律 `gap_m`。フォークリフト通路3.0mは未対応 |
| 回転しない | 設備は縦横を入れ替えられない |

**直す順番は [要件定義.md](要件定義.md) の第8節。**
最初の1つ（`generator` から条件判定を呼ぶ）を直すと、**「条件を満たす案だけが残る」**ようになり、
このツールの意味が大きく変わる。
