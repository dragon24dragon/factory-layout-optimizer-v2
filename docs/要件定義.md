「工場建設時のレイアウト設計最適化アルゴリズム PoC」（Python・フルリモート）を題材にした**自主制作**。

> **この要件は、ChatGPT に発注者（建設会社の設計担当）役を依頼した模擬ヒアリングで決めたものです。**

---

## 1. 解決したい課題

工場のレイアウトは、**モノが動く距離が操業コストに直結する。**
しかし「重ならない」「はみ出さない」「安全上の離隔を取る」といった条件を満たす配置を、
**人手で何案も作って比べるのは大変**で、条件を1つ変えればやり直しになる。

**条件を入力すれば配置案を複数自動で作り、搬送距離で順位をつけて見比べられる**状態を目指す。

## 3. 工程と搬送量

**同じ工場で3つの流し方が混在する。**

| パターン | 割合 | 流れ |
|---|---:|---|
| A | **50%** | 原材料 → 切断 → マシニング → 仕掛品 → 検査 → 梱包 → 完成品 → 出荷 |
| B | **30%** | 原材料 → 切断 → **旋盤** → 仕掛品 → 検査 → 梱包 → 完成品 → 出荷 |
| C | **20%** | 原材料 → 切断 → マシニング/旋盤 → **溶接** → 仕掛品 → 検査 → 梱包 → 完成品 → 出荷 |

### 1日あたりの搬送回数（距離の重み）

| 区間 | 回/日 |
|---|---:|
| 原材料 → 切断機 | **30** |
| 切断機 → マシニングセンタ | 15 |
| 切断機 → 旋盤 | 9 |
| マシニング/旋盤 → 溶接 | 6 |
| マシニング/旋盤 → 仕掛品 | 24 |
| 溶接 → 仕掛品 | 6 |
| 仕掛品 → 検査 | **30** |
| 検査 → 梱包 | **30** |
| 梱包 → 完成品 | **30** |
| 完成品 → 出荷 | **30** |

**距離だけでなく「何回運ぶか」を掛けて評価する。** これが v1 との最大の違い。

## 4. 守る条件（安全基準）

| 条件 | 値 |
|---|---:|
| フォークリフト通路の最小幅 | 3.0 m |
| 歩行者通路の最小幅 | 1.2 m |
| 設備と設備の最小距離 | 2.0 m |
| 設備と壁・柱の最小距離 | 1.0 m |
| 非常口前の確保（幅×奥行） | 3.0 m × 3.0 m |
| 溶接エリア ↔ 原材料置場 | **5.0 m 以上** |
| 溶接エリア ↔ 完成品置場 | **5.0 m 以上** |

**溶接エリアを5m離すのは、火花が飛ぶため。**
v1 では「重ならなければよい」までしか考えていなかった。**安全は、距離の数字になる。**

**固定物（柱・非常口・電気室）は、自分では思いつかなかった項目。**
工場には動かせないものがあり、それを避けて配置する必要がある。
**現場を知っていることと、それを「システムの入力」として書き出すことは別の作業だった。**
（経緯は [ヒアリングメモ.md](ヒアリングメモ.md)）

| 条件 | 値 |

| 完成品置場 ↔ 出荷口 | 10 m 以内 |

## 6. 出力の条件

| 項目 | 値 |

| 表示 | 上位3案を配置図つきで比較 |

## 7. 実装の状況（2026年10月1日時点）

**「決めた条件」と「動いている範囲」を分けて書く。**

### 実装され、テストもあるもの（37件すべて成功）

| 機能 | 置き場所 |
|---|---|
| 工場からはみ出さない判定 | `constraints.is_inside_factory` |
| 設備どうしの重なり判定 | `constraints.areas_overlap` |
| 面と面の最短距離の計算 | `constraints.distance_between_areas` |
| 最小距離を満たすかの判定 | `constraints.has_minimum_distance` |
| 壁からの離隔の判定 | `constraints.has_wall_clearance` |
| 柱からの離隔の判定 | `constraints.has_pillar_clearance` |
| 非常口前に重ならない判定 | `constraints.is_clear_of_emergency_exit` |
| 溶接の離隔（既定5.0m）の判定 | `constraints.has_welding_clearance` |
| 搬送回数で重みづけした距離の合計 | `scoring.total_weighted_flow_distance` |
| 候補をスコア順に並べる | `scoring.rank_candidate_layouts` |
| 入力値の検査（工場・設備） | `validation.py` |

### まだ接続されていないもの（**ここが次の課題**）

| 決めた条件 | 現状 |
|---|---|
| 安全条件の判定（壁・柱・非常口・溶接） | **関数はあるが、`generator.py` から呼ばれていない** |
| 固定物（受入口・出荷口・非常口・柱・電気室） | **データにあるが、配置生成では使っていない** |
| 通路幅（フォークリフト3.0m・歩行者1.2m） | 未実装。設備間は一律 `gap_m`（既定2.0m） |
| 工程パターン A/B/C の割合 | 未使用。評価は `daily_flows` の回数のみ |
| できれば満たしたい条件（受入口・出荷口の近さ、検査と梱包の近さ） | 未実装 |
| 処理時間の計測（30/60/120秒） | 計測していない |

**候補の作り方も単純なまま。** 設備を左下から順に詰め、**並べる順番をずらして候補を作っている**だけ
（`generator.generate_candidate_layouts`）。条件を満たすかの再探索はしていない。

### 距離の測り方が v1 と変わった

| | v1 | **v2** |
|---|---|---|
| 距離 | マンハッタン距離（縦＋横） | **直線距離**（中心間・`math.hypot`） |
| 重み | なし | **1日の搬送回数を掛ける** |

## 8. 次にやること（優先順）

1. **`generator` から安全条件を呼ぶ**（置いた位置が条件を満たすか確認し、だめなら別の位置を試す）
2. **固定物を配置に反映する**（柱・電気室・非常口前を「置けない場所」として扱う）
3. **通路幅を扱う**（フォークリフト通路3.0mを前提にした間隔）
4. **処理時間を測って表示する**（上限120秒の条件に対する実測）
5. できれば満たしたい条件を**減点方式**で評価に入れる
